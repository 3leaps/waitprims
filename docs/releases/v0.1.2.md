# waitprims v0.1.2

Release-kit hygiene. No library API change is intended. This commit is
the release-prep content; it does not create a git tag, publish to
crates.io, or change repository visibility.

## Highlights

- **Independent release leaves**: `release-clean`, `release-download`,
  `release-notes`, `release-checksums`, `release-sign`, and
  `release-export-keys` have no write-chain precursors. A mid-chain
  target does not wipe `dist/release/` or re-download GitHub assets.
- **Serialized walk only on `make release`**: clean, download, notes,
  checksums, sign, export-keys, upload. Verification runs once, as
  the upload grouping prerequisite. Matches the sysprims leaf
  pattern; notes stay before checksums so they remain in the signed
  set.
- **`publish` stays `false`**. `make release-check` still packages and
  does not run `cargo publish`.
- CLI `--version` test reads the workspace `VERSION` file instead of
  a hardcoded pin.

## Not in this release

- No API, schema, or CLI behavior change
- No crates.io publish
- No visibility change
- No git tag in this commit

## Verification

- `cargo test --workspace --locked`
- `cargo fmt --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `make release-check` (`cargo package`, publish still false)
- After populating `dist/release/`, `make release-export-keys` does not
  remove or re-download existing artifacts
